Protect pull requests

CI setup

Run the same scanner on every change and block new risk before merge.

Three steps

Add SkillCheck to GitHub Actions

  1. 1
    Commit the policy

    Add skillcheck.config.json to the repository root.

  2. 2
    Add the workflow

    Use the generated Action configuration.

  3. 3
    Protect the branch

    Require the SkillCheck check before merge.

.github/workflows/skillcheck.yml

name: SkillCheck
on:
  pull_request:
  push:
    branches: [main]
permissions:
  contents: read
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: sixscripts-ai/SkillCheck@v1
        with:
          path: .
          config: skillcheck.config.json
          mode: auto

Product boundary

Docs

SkillCheck provides deterministic static evidence. Runtime behavior still requires evaluation, sandboxing, and review.

01

Scan packages

Analyze SKILL.md, executable files, manifests, workflows, environment references, and package structure.

02

Bind exact drafts

Every report includes package and policy fingerprints so stale evidence cannot approve changed code.

03

Compare changes

Pull-request mode isolates new findings, resolved findings, permission expansion, and score changes.

04

Complete runtime proof

Attach evaluations and sandbox results before a production system treats a package as release-ready.

Static-analysis boundary

SkillCheck does not execute uploaded packages, prove runtime behavior, or replace human approval for high-impact actions.
